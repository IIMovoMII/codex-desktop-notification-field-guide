# 消息投递与积压恢复

[English](delivery.en.md)

状态机生成通知，CC Connect 发送器负责投递。两者失败原因分开记录。

## 一条消息的生命周期

~~~text
持久入队 → 到期尝试 → 桥接明确接受 → 本地记账
                ↘ 暂时失败：保留、退避
                ↘ 需要处理：保留、暂停该目标
                ↘ 确认丢失：标为结果不确定
~~~

通知保留本地稳定编号、任务／轮次关联、状态、脱敏内容、事件时间、目标版本、尝试次数与下次重试时间。目标要明确到 CC Connect 项目和接收会话；不要默认选择“第一个活跃会话”。

在已核对的 [CC Connect v1.5.0 发送命令](https://github.com/chenhg5/cc-connect/blob/17c61062c2f9ce9bcdd45a2082e491f9743a2770/cmd/cc-connect/send.go)中，成功只输出通用文字；[内部接口](https://github.com/chenhg5/cc-connect/blob/17c61062c2f9ce9bcdd45a2082e491f9743a2770/core/api.go)返回 `status=ok`。这不是手机已读回执，也不包含可强求的远端消息编号。升级后重新核对实际契约。

桥接接受后、记账前崩溃，或者网络超时但远端已收到，都会留下不确定窗口。没有远端幂等能力时，不能同时保证“绝不漏发”和“绝不重复”。保留同一通知编号，按所选策略有限重试或留待检查；不能把所有不确定项称为可安全无限重发。

## 有界重试

暂时网络／服务错误使用退避、抖动和平台返回的重试时间，持久保存下次尝试时刻。给每次发送设实际超时，别让一条挂起阻塞全部队列；发送器内部未提供超时的路径，由调用方控制。

区分认证／目标失效、额度暂时耗尽、网络故障与结果不确定。额度到期可恢复，不应一律判成永久失败；未知失败保留记录、少量尝试后暴露原因。需要重绑或修复配置的目标暂停自动重试，修复后允许定向恢复。

处理已到期队列时用有限批量、速率限制与公平调度，避免固定每轮只发一条把大量消息无故拖很久，也避免积压恢复时无上限轰炸。旧消息保留原发生时间，可标“补发”。过期、合并或丢弃由用户预先选择，不静默清空。

## 为什么重启后收到一堆

先查四项：最老待发时间、最后失败类别、下次重试时间、发送器实际存活时间。

- 已入队但进程随 Desktop 退出：磁盘上保留了消息，重试却暂停到下一次运行。
- 进程活着但发送接口不可用：可能是启动未就绪、认证、网络、目标或本地套接字问题。
- 接口正常却迟迟不发：检查重试时钟、过期租约、调度与是否只靠新钩子唤醒。
- 已接受却再次发送：检查持久记账、通知身份和不确定投递窗口。

不要看到“积压”就给 CC Connect 定责，或者添加全盘秒级扫描。

## Desktop 退出策略

| 策略 | 行为 |
| --- | --- |
| 严格随 Desktop 停止 | 保存剩余队列，下次启动补发；退出后不承诺重试 |
| 限时发送收尾 | 停止任务观察，只保留发送器和专用桥接；清空或到期后退出 |
| 独立发送服务 | 可在 Desktop 关闭后重试，但用户需接受后台常驻 |

本包不替用户选择。限时收尾必须处理断网、关机、超过期限、再次打开 Desktop，以及恰好在退出边界入队的消息；到期留队并记录原因，不能无限等待“必定发完”。

共享 CC Connect 只连接／断开，不能结束其进程或覆盖公共配置。重启专用实例也要确认进程身份，避免误杀其他用途。

## 本地接口与消息内容

验证发送路径直接发送统一通知，不调用 CC Connect 的 Agent 扩写，也不把其控制台日志当提醒正文。优先通过参数数组或 stdin 传递内容，避免 shell 拼接、特殊字符错误和命令行长度限制。

Windows 曾出现桥接显示已连接，但本地套接字路径导致发送失败。要用实际运行时测试“创建、连接、收发”，不要只看文件或旧的 ready 日志。若缩短路径，说明是别名还是迁移，保持只有一份数据；实测长度不是 Windows 永久通用上限。

## 可选入站控制

仅提醒或双向由用户决定，不把“默认全拒绝”当本包统一要求。要控制已有 Desktop 对话时，通知可显示短别名，由本地表映射到稳定任务 ID；选定目标后回复“继续”，比猜最近打开的窗口可靠。

启用前明确允许的发送者、动作、目标、忙碌时处理、防重复和撤销方式。普通文本不能直接拼成命令。CC Connect 的 CLI Agent 会话不等于 Desktop 已有对话；先验证当前版本的续跑入口能唤醒目标、在原历史中追加且不会开错新会话。工具存在不证明这些语义，未验证就把远控标为待实现。

## 换平台与恢复

暂停该目标的发送，按[平台选择](cc-connect-platform-selection.md)完成新绑定，先验证合成通知，再切换目标。旧队列由用户选择保留旧目标、迁移或清理；保留目标版本，防止误发到新的群或账号。状态机与读取游标不必因此重建。
